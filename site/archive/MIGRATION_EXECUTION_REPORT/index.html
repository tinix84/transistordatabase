    TDB JSON Structure¶

    All migrated files follow the standardized TDB schema:

    {
  "metadata": {
    "name": "transistor_id",
    "type": "IGBT|MOSFET|SiC-MOSFET|GaN-Transistor|Diode",
    "manufacturer": "manufacturer_name",
    "housing_type": "TO263|LDPAK|etc",
    "import_source": "source_format:filename",
    "import_date": "ISO8601_timestamp"
  },
  "electrical_ratings": {
    "v_abs_max": float,      // Volts
    "i_abs_max": float,      // Amperes
    "i_cont": float,         // Amperes
    "t_j_max": float         // Celsius
  },
  "thermal_properties": {
    "r_th_jc": float,        // K/W
    "r_th_cs": float,        // K/W
    "housing_area": float,   // m²
    "cooling_area": float    // m²
  },
  "switch": {
    "channel_data": [...],
    "e_on_data": [...],
    "e_off_data": [...],
    "gate_charge_curves": [...],
    "soa": [...]
  },
  "diode": {
    "channel_data": [...],
    "e_rr_data": [...]
  },
  "c_oss": [...],
  "c_iss": [...],
  "c_rss": [...]
}

    Data Quality Analysis¶

    Quality Scoring Methodology¶

    • Completeness Score: 0-100%, calculated from:
    • Required fields (name, type, manufacturer, V_abs_max, I_abs_max): 10 points each
    • Thermal properties (R_th_jc, R_th_cs, housing_area): 5 points each
    • Curve data (channel_data, switching losses, gate charge): 15 points each
    • Capacitance curves (C_oss, C_iss, C_rss): 5 points each

    Duplicate Detection & Conflict Resolution¶

    Summary¶

    • Duplicates Found: 313 conflicts across 245 unique transistor IDs
    • Cause: Most duplicates are the same device from multiple sources:
    • File Exchange JSON + TDB native database (exact duplicates)
    • PLECS XML IGBT + separate Diode files (same part number, different files)
    • CSV utility data + PLECS XML versions

    Conflict Resolution Strategy¶

    • Automatic: Compared data completeness scores
    • If new data > existing data by > 5%: recommendation = "keep_new"
    • Otherwise: recommendation = "keep_existing"
    • Result: 313 conflicts logged in CONFLICTS_FOR_REVIEW.json for manual review

    Error Recovery¶

    The migration implements robust error handling: - Validates each file before processing - Catches and logs format-specific conversion errors - Continues processing remaining files on error - Maintains detailed error log (migration.log)

    File Format Conversions¶

    TDB Native → TDB¶

    • Input: File Exchange JSON format (flat structure with root-level fields)
    • Output: Wrapped in metadata/electrical_ratings/thermal_properties
    • Transformation: Direct mapping with structural reorganization
    • Result: 50/50 successful (100%)

    File Exchange JSON → TDB¶

    • Input: JSON with root-level: name, type, manufacturer, v_abs_max, etc.
    • Output: Properly nested TDB JSON structure
    • Transformation:
    • Extract root fields to metadata/electrical_ratings/thermal_properties
    • Preserve switch/diode/capacitance sub-structures as-is
    • Add import metadata with source tracking
    • Result: 25/25 successful (100%)

    PLECS XML → TDB¶

    • Input: PLECS Semiconductor Library XML with switching losses and thermal models
    • Output: TDB JSON with extracted curve data
    • Transformation:
    • Extract device class, vendor, part number → metadata
    • Parse switching loss data (E_on, E_off) → switch.e_on_data/e_off_data
    • Parse conduction loss (I-V characteristics) → switch.channel_data
    • Parse Foster thermal model → switch.thermal_foster
    • Result: 502/504 successful (99.6%)

    CSV → TDB¶

    • Input: CSV files with header row containing electrical parameter columns
    • Output: TDB JSON with basic electrical ratings
    • Transformation:
    • Parse CSV headers (name, type, manufacturer, v_ds, i_d, r_th_jc, etc.)
    • Map to TDB electrical_ratings and thermal_properties
    • Create empty switch/diode structures
    • Result: 6/6 successful (100%)

    Migration Script Features¶

    The migrate_to_tdb.py script includes:

    Core Capabilities¶

    1. Multi-format support: JSON, XML (PLECS), CSV
    2. Format detection: Automatic detection and routing to appropriate converter
    3. Duplicate detection: Transistor ID matching and conflict logging
    4. Quality scoring: Completeness calculation for all records
    5. Validation: Schema conformance checks and value range validation
    6. Error recovery: Graceful handling of malformed files with detailed logging

    Advanced Features¶

    • Dry run mode: Preview migration without writing files
    • Namespace handling: Support for both prefixed and non-prefixed XML namespaces
    • Flexible CSV parsing: Dialect detection and case-insensitive header matching
    • Import tracking: Every file includes source and timestamp metadata
    • Progress reporting: Real-time feedback every 50 files

    Output Reports¶

    1. MIGRATION_REPORT.json: Comprehensive statistics and sample results
    2. CONFLICTS_FOR_REVIEW.json: All 313 duplicates with recommendations
    3. migration.log: Detailed debug log with full error traces

    Recommendations for Follow-up¶

    Phase 2: Conflict Resolution¶

    1. Review CONFLICTS_FOR_REVIEW.json for duplicates with significant quality differences
    2. For critical devices (high-volume manufacturers), merge best data from each source
    3. Update import metadata to record manual conflict resolution decisions

    Phase 3: Data Enrichment¶

    1. Import switching loss curves from PLECS XML more completely
    2. Add gate charge curves and SOA curves where available
    3. Cross-reference manufacturer datasheets for missing thermal parameters

    Phase 4: Integration¶

    1. Load migrated database into TDB core models for API access
    2. Validate against TDB schema using core validation services
    3. Deploy to production transistor library

    Known Issues¶

    1. Low quality scores: Expected due to source data limitations (not an error)
    2. Corrupted XML file: C4D05120A.xml in archive_ntbees2 has XML syntax errors
    3. Action: Delete or request replacement from source
    4. Diode as separate files: PLECS XML represents IGBT and Diode separately
    5. Improvement: Consider merging IGBT + corresponding Diode into single record
