    Phase 6: Archive Integration & Power Features - Implementation Complete¶

    Status: ✅ COMPLETE Date: 2025-02-14 Phase Duration: Phase 6 (Final Phase)

    Executive Summary¶

    Phase 6 successfully integrates production-ready archive features into the web interface, including PLECS XML import (372+ device support), analytical switching loss models (Biela, gate charge), and LTspice Double Pulse Test netlist generation. This completes the 6-phase implementation plan, bringing the web interface to full feature parity with the desktop GUI.

    Backend Implementation: - 6 new REST API endpoints - Integration with existing plecs_importer.py, analytical_models.py, and ltspice_dpt.py modules - 46 total API routes across all 6 phases

    Frontend Implementation: - 3 major Vue 3 components (PLECSImporter, AnalyticalCalculator, DPTManager) - 14 total components created across all phases - Full-featured UI for bulk import, analytical calculations, and DPT management

    class BielaModelRequest(BaseModel):
    """Request schema for Biela analytical model calculations."""

    # Device parameters
    c_oss: float = Field(..., description="Output capacitance in F", gt=0)
    q_g: float = Field(..., description="Total gate charge in C", gt=0)
    v_plateau: float = Field(..., description="Gate plateau voltage in V", gt=0)
    r_g_on: float = Field(..., description="Gate resistance turn-on in Ohm", gt=0)
    r_g_off: float = Field(..., description="Gate resistance turn-off in Ohm", gt=0)

    # Operating conditions
    v_dc: float = Field(..., description="DC bus voltage in V", gt=0)
    i_load: float = Field(..., description="Load current in A", gt=0)
    t_j: float = Field(25.0, description="Junction temperature in deg C")

    # Optional curve generation
    i_min: Optional[float] = Field(None, description="Minimum current for curve in A")
    i_max: Optional[float] = Field(None, description="Maximum current for curve in A")
    i_points: int = Field(50, description="Number of points in curve", ge=2, le=1000)

    Features: - Device parameter validation (C_oss, Q_g, gate resistances) - Operating condition constraints (positive voltages/currents) - Optional curve generation over current range (10-1000 points)

    Endpoint 2: Biela Model Calculation¶

    @app.post("/api/analytical/biela")
async def calculate_biela(request: BielaModelRequest) -> Dict[str, Any]

    Purpose: Calculate switching losses using Biela analytical model

    Request: 

    {
  "c_oss": 150e-12,
  "q_g": 50e-9,
  "v_plateau": 5.0,
  "r_g_on": 10.0,
  "r_g_off": 10.0,
  "v_dc": 400.0,
  "i_load": 20.0,
  "t_j": 25.0,
  "i_min": 0,
  "i_max": 50,
  "i_points": 50
}

    Response: 

    {
  "operating_point": {
    "v_dc": 400.0,
    "i_load": 20.0,
    "t_j": 25.0
  },
  "results": {
    "e_on": 0.000123,
    "e_off": 0.000087,
    "e_total": 0.000210
  },
  "curve": {
    "currents": [0, 1.02, 2.04, ..., 50],
    "e_on": [0, 6.3e-6, 1.25e-5, ..., 3.1e-4],
    "e_off": [0, 4.5e-6, 8.9e-5, ..., 2.2e-4],
    "e_total": [0, 1.08e-5, 2.14e-5, ..., 5.3e-4]
  }
}

    Features: - Single operating point calculation (E_on, E_off, E_total) - Optional curve generation over current range - Temperature compensation (+0.3%/K above 25°C) - Energy values in Joules (frontend converts to µJ)

    Physics-Based Model: 1. Turn-On Energy: E_on = 0.5 × V_dc × I_load × (t_ri + t_fv) + 0.5 × C_oss × V_dc² - t_ri: Current rise time (gate charging through Miller plateau) - t_fv: Voltage fall time (C_oss discharge) 2. Turn-Off Energy: E_off = 0.5 × V_dc × I_load × (t_rv + t_fi) - t_rv: Voltage rise time (C_oss charging) - t_fi: Current fall time (gate discharging)

    {
  "parameters": {
    "q_gs": 1e-8,
    "q_gd": 1.5e-8,
    "q_g": 5e-8,
    "v_th": 2.5,
    "v_plateau": 5.0,
    "r_g_total": 11.0
  },
  "turn_on_times": {
    "t_delay": 15.3,
    "t_rise": 8.7,
    "t_fall_v": 27.5,
    "t_total": 51.5
  },
  "turn_off_times": {
    "t_delay": 12.8,
    "t_rise_v": 33.0,
    "t_fall_i": 6.7,
    "t_total": 52.5
  }
}

    Features: - All times in nanoseconds (converted from seconds in backend) - Separate turn-on and turn-off timing analysis - Breakdown into delay, rise/fall phases - Total transition time for each direction

    Model Equations: - Turn-On Delay: t_d = R_g × Q_gs × ln(V_driver / (V_driver - V_th)) - Current Rise: t_ri = R_g × Q_rise / (V_driver - V_plateau) - Voltage Fall: t_fv = R_g × Q_gd / (V_driver - V_plateau)

    @app.post("/api/dpt/generate_netlist")
async def generate_dpt_netlist(transistor_id: str, config: DPTConfigRequest) -> Dict[str, str]

    Purpose: Generate LTspice Double Pulse Test netlist for a transistor

    Request: 

    {
  "transistor_id": "IPW60R045CP",
  "config": {
    "v_dc": 400.0,
    "i_target": 20.0,
    "l_load": 100e-6,
    "r_g_on": 10.0,
    "r_g_off": 10.0,
    "v_g_on": 15.0,
    "v_g_off": -5.0,
    "t_dead": 5e-6,
    "t_pulse2": 2e-6
  }
}

    Response: 

    {
  "netlist": "Version 4\nSHEET 1 880 680\n...",
  "transistor_name": "IPW60R045CP",
  "config": {
    "v_dc": 400.0,
    "i_target": 20.0,
    "r_g_on": 10.0,
    "r_g_off": 10.0
  }
}

    Features: - Full LTspice .asc netlist format - Double pulse waveform generation - Load inductance sizing (first pulse duration calculated to reach target current) - Gate driver circuit with configurable resistances - Measurement probes for V_ds, I_d, V_gs

    Circuit Topology: 

    V_dc --+-- DUT (Switch) --+-- Load Inductor (L_load) -- GND
       |                  |
       +-- Freewheeling Diode

Gate Driver: V_on/V_off with R_g_on/R_g_off
Pulse 1: Charge inductor to I_target
Dead Time: 5 µs
Pulse 2: Turn-off transient (measure E_off)

    State Management¶

    const files = ref([])           // Array of FileItem objects
const importing = ref(false)    // Import in progress flag
const importResults = ref([])   // Array of PLECSImportResponse objects

// Computed properties
const pendingCount = computed(() =>
  files.value.filter(f => f.status === 'pending').length
)
const totalImported = computed(() =>
  importResults.value.reduce((sum, r) => sum + r.transistors_imported, 0)
)
const allImportedIds = computed(() => {
  const ids = []
  importResults.value.forEach(r => ids.push(...r.transistor_ids))
  return ids
})

    Import Flow¶

    1. User uploads files → addFiles() validates size, adds to queue
    2. User clicks Import → startImport() processes sequentially
    3. For each file:
    4. Set status to 'uploading'
    5. Call transistorApi.importPLECS(file)
    6. Update status to 'success' or 'error'
    7. Store result in importResults
    8. Emit 'import-complete' event with total count and IDs

    // In parent component
<PLECSImporter

    Key Functions¶

    async function loadDPTData() {
  dptData.value = await transistorApi.getDPTData(selectedTransistorId.value)
}

async function generateNetlist() {
  generating.value = true
  generatedNetlist.value = await transistorApi.generateDPTNetlist(
    selectedTransistorId.value,
    dptConfig.value
  )
  generating.value = false
}

async function validateData() {
  validating.value = true
  validationResults.value = await transistorApi.validateDPTData(
    selectedTransistorId.value
  )
  validating.value = false
}

function copyNetlist() {
  navigator.clipboard.writeText(generatedNetlist.value.netlist)
  alert('Netlist copied to clipboard!')
}

function downloadNetlist() {
  const blob = new Blob([generatedNetlist.value.netlist], { type: 'text/plain' })
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = `${generatedNetlist.value.transistor_name}_DPT.asc`
  link.click()
}

    Known Limitations¶

    Backend Limitations¶

    1. PLECS Import:
    2. Limited to XML format (no binary .plecs files)
    3. Some PLECS-specific metadata not preserved

    4. Thermal model conversion may lose precision

    5. Analytical Models:

    6. Biela model assumes inductive switching (not valid for capacitive loads)
    7. Gate charge model ignores parasitic inductances

    8. IGBT model not yet implemented in web interface

    9. DPT Netlist:

    10. Requires PyLTSpice for simulation (not included in web backend)
    11. No automatic waveform analysis (manual inspection required)
    12. Single device only (no half-bridge support)

    Frontend Limitations¶

    1. File Upload:
    2. No drag-and-drop folder support
    3. 10MB file size limit (configurable)

    4. No resume capability for failed uploads

    5. Curve Plotting:

    6. Limited to 1000 points for performance
    7. No export to CSV/Excel

    8. No zoom/pan persistence across tab switches

    9. Validation:

    10. DPT validation rules hardcoded (not user-configurable)
    11. No comparison to industry standards (IEC, MIL-STD)
    12. No automated test report generation
