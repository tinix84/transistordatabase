    Phase 3: Export Preview & Batch Operations¶

    Backend Implementation¶

    1. Export Preview Endpoint¶

    Route: GET /api/transistors/{transistor_id}/export/{format}/preview

    Features: - Preview first 100 lines of text exports - File size and line count metadata - Supports: JSON, CSV, SPICE, PLECS, LTspice - Truncation indicator for large files

    Response Format: 

    {
  "preview": "... first 100 lines ...",
  "total_lines": 523,
  "preview_lines": 100,
  "file_size": 45823,
  "file_name": "IGBT_1200V_100A.json",
  "truncated": true
}

    2. Batch Export Endpoint¶

    Route: POST /api/transistors/batch_export

    Features: - Export 1-100+ transistors simultaneously - ZIP archive generation - Progress tracking - Error handling per transistor - Format-specific options support

    Request: 

    {
  "transistor_ids": ["T1", "T2", "T3"],
  "format": "json",
  "options": {}
}

    Returns: ZIP file with all exports

    3. Format-Specific Options¶

    Integrated PLECSExportOptions and MATLABExportOptions from schemas: - PLECS: recheck, include_thermal, include_losses - MATLAB: variable_name, struct_array

    UI Elements: - Format selector grid - Dark-themed code preview (Monaco-style) - Metadata badges - Action buttons (Copy, Download)

    2. BatchExportPanel Component¶

    File: gui_web/src/components/BatchExportPanel.vue (650 lines)

    Features: - Multi-select transistor list with checkboxes - Search and filter (by type, name) - Select All / Clear Selection actions - Export format dropdown - Format-specific options (expandable) - Progress bar with live updates - Estimated size and time calculations - Success/error handling

    Statistics Cards: - Transistors Selected count - Estimated Size - Estimated Time

    Progress Tracking: - Real-time progress bar - Current/Total counter - Status messages

    ✅ Preview-before-download - Inspect exports without downloading ✅ Batch operations - Export 10+ transistors in one click ✅ ZIP archiving - Organized multi-file exports ✅ Progress tracking - Visual feedback during exports ✅ Error resilience - Individual failures don't stop batch ✅ Format descriptions - User education built-in

    Phase 4: Real Topology Calculations¶

    Backend Implementation¶

    1. TopologyCalculatorService¶

    File: gui_web/backend/topology_service.py (250 lines)

    Supported Topologies: - Buck converter - Boost converter - Buck-Boost converter

    Calculation Features: - Duty cycle calculation - Current stress analysis (RMS, average) - Voltage stress analysis - Conduction loss estimation - Switching loss calculation - Efficiency calculation - Waveform generation (1000 points/period)

    Integration: - Uses real transistor data when provided - Falls back to simplified models - Interpolates channel characteristics - Interpolates switching losses from curves

    2. API Endpoints¶

    Calculate Single Topology: POST /api/topology/calculate

    {
  "topology": "buck",
  "parameters": {
    "v_in": 400,
    "v_out": 48,
    "p_out": 1000,
    "f_sw": 100000,
    "t_j": 25,
    "v_g": 15,
    "r_g_on": 10,
    "r_g_off": 10
  },
  "transistor_id": "MOSFET_650V_50A"
}

    Response includes: - Calculated duty cycle, currents, voltages - Loss breakdown (conduction, switching on/off, diode) - Performance metrics (P_in, P_out, efficiency) - Component stress (voltage/current utilization) - Time-domain waveforms (current, voltage)

    Compare Topologies: POST /api/topology/compare

    Calculates all 3 topologies simultaneously and returns: - Individual results for each topology - Efficiency comparison - Best topology recommendation

    Get Recommendations: GET /api/topology/recommendations

    ?topology=buck&v_in=400&v_out=48&p_out=1000

    Returns transistors sorted by suitability: - Voltage/current requirements - Utilization score (target: 70-80%) - Safety margins - Top 10 recommendations

    Calculation Details¶

    Duty Cycle Formulas¶

    Buck:       D = V_out / V_in
Boost:      D = 1 - (V_in / V_out)
Buck-Boost: D = V_out / (V_in + V_out)

    Current Stress¶

    I_sw_rms = I_out * sqrt(D)           # Buck
I_sw_rms = I_in * sqrt(D)            # Boost
I_diode_rms = I_load * sqrt(1 - D)   # Common

    Loss Calculation¶

    P_cond = R_ds_on * I_rms²
P_sw_on = E_on(I, V, R_g, T_j) * f_sw
P_sw_off = E_off(I, V, R_g, T_j) * f_sw
P_diode = V_f * I_diode_rms

η = P_out / (P_out + P_losses) * 100%

    Key Features¶

    ✅ Real calculations - Uses transistor data when available ✅ 3 topologies - Buck, Boost, Buck-Boost support ✅ Waveform generation - 1000-point current/voltage traces ✅ Loss breakdown - Detailed power loss analysis ✅ Smart recommendations - Transistor suggestions by utilization ✅ Comparison mode - Evaluate all topologies side-by-side

    Phase 5: Settings & Advanced Features¶

    Backend Implementation¶

    1. User Settings Management¶

    Endpoints: - GET /api/settings/user - Retrieve settings - PUT /api/settings/user - Update settings - POST /api/settings/user/reset - Reset to defaults

    Settings Schema: 

    {
  "theme": "light",
  "default_filters": {},
  "favorite_transistors": ["T1", "T2"],
  "recent_transistors": ["T3", "T4", "T5"],
  "plot_preferences": {},
  "auto_save": true
}

    Storage: - In-memory dict (current implementation) - Database-ready interface - Per-user isolation

    2. Advanced Search¶

    Route: POST /api/transistors/search/advanced

    Filter Capabilities: - Type filter (IGBT, MOSFET, etc.) - Voltage range (min/max) - Current range (min/max) - Feature flags (has_gate_charge, has_switching_losses) - Manufacturer filter - Housing type filter

    Sorting: - Any field (v_abs_max, i_abs_max, name, etc.) - Ascending/descending

    Pagination: - Page number - Items per page (1-100) - Total count returned

    Request Example: 

    {
  "filters": {
    "type": ["IGBT", "MOSFET"],
    "v_abs_max": {"min": 600, "max": 1200},
    "has_gate_charge": true
  },
  "sort_field": "v_abs_max",
  "sort_order": "desc",
  "page": 1,
  "per_page": 20
}

    Response: 

    {
  "results": [ /* transistor objects */ ],
  "pagination": {
    "page": 1,
    "per_page": 20,
    "total": 157,
    "pages": 8
  }
}

    3. Favorites Management¶

    Endpoints: - POST /api/favorites/add - Add to favorites - POST /api/favorites/remove - Remove from favorites - GET /api/favorites/list - Get favorites list

    Features: - Per-user favorites - Quick access to frequently used transistors - Persistent across sessions

    Known Limitations & Future Work¶

    Phase 3 Limitations¶

    1. Preview Binary Formats: No preview for MATLAB/GeckoCIRCUITS

    2. Future: Add hex/binary viewers

    3. Batch Progress: Simulated progress (single API call)

    4. Future: True streaming with WebSockets

    5. Export Options: Limited format-specific customization

    6. Future: Advanced PLECS template editor

    Phase 4 Limitations¶

    1. Simplified Models: Triangular current approximation

    2. Future: Integration with full ConverterBase methods

    3. Single Operating Point: No load sweep analysis

    4. Future: Multi-point efficiency curves

    5. No Thermal Transient: Steady-state only

    6. Future: Transient thermal simulation

    Phase 5 Limitations¶

    1. In-Memory Settings: Lost on server restart

    2. Future: Database persistence (PostgreSQL/MongoDB)

    3. No Authentication: Single "default" user

    4. Future: OAuth/JWT authentication

    5. Limited Favorites: No folders/tags

    6. Future: Favorites organization
