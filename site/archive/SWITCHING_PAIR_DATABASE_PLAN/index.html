    Switching-Pair Database Architecture Plan¶

    Core Principle¶

    Switching loss is a commutation-system phenomenon, not a datasheet scalar.

    Every entry in the database represents a switching pair — the minimum unit of a converter leg. A "single device" is the special case where both sides are the same device (standard DPT assumption).

    Architecture Overview¶

    Single Unified Database¶

    transistordatabase/switching_pairs/
├── Cree_C3M0075120K.json                              # Self-pair (datasheet)
├── Infineon_IPW65R048CFDA.json                         # Self-pair (datasheet)
├── Infineon_IPW65R048CFDA__ST_STTH30RQ06DY.json        # MOS + external diode
├── Infineon_IPW65R080CFDA__Infineon_IPW65R080CFDA.json # MOS + MOS (half-bridge)
├── 10x_ST_SCTW100N65G2AG.json                          # 10 parallel (self-pair)
└── ...

    One JSON file per switching pair. Git-friendly, easy diffs, clear ownership.

    File naming convention: {high_side}__{low_side}.json (double underscore separator) - Self-pair: just {device_id}.json - Parallel: {N}x_{device_id}.json or {N}x_{device_id}__{M}x_{device_id2}.json

    Migration Strategy¶

    Source Classification¶

    Source Count Format Migration Action
    sc/db/scData/*.mat 187 MATLAB Parse → switching pairs
    sc/data//.xml 504 PLECS XML Parse → self-pairs (conduction + switching from XML)
    TDB transistors/ 24 JSON Wrap as self-pairs (source=datasheet)
    File Exchange 25 JSON Wrap as self-pairs (source=datasheet)

    .mat Filename Parsing Rules¶

    Pattern                                    Action
─────────────────────────────────────────────────────────────────
Vendor_PartNumber.mat                     → Self-pair (base device)
Vendor_PartNumber1_with_Vendor_PN2.mat    → Combination pair (MIGRATE)
Vendor_PN1_with_SiC_Diode.mat            → SKIP (2nd P/N unclear)
N_x_Vendor_PartNumber.mat                → Parallel self-pair
Vendor_PN_125C.mat                        → MERGE into base device temp array
Vendor_PN_Eon.mat                         → MERGE into base device E_on data
Vendor_PN_Eoff.mat                        → MERGE into base device E_off data
Vendor_PN_Vfwd.mat                        → MERGE into base device conduction data
Vendor_PN_Vrev.mat                        → MERGE into base device reverse conduction
Vendor_PN_reverse_ON.mat                  → MERGE into base device as reverse mode
Adjusted_Vendor_PN.mat                    → SKIP (use original only)
Vendor_PN_HB_Sw+Diode.mat                → Combination pair (switch + body diode mode)
Vendor_PN_HB_Sw+Sw.mat                   → Combination pair (synchronous mode)

    Migration Phases¶

    Phase A: .mat File Migration (PRIMARY - 187 files)¶

    1. Parse filename → determine pair type and constituent devices
    2. Load .mat with scipy.io.loadmat()
    3. Extract 25 ScDataGeneric fields from structured array
    4. Group temperature variants by base device name
    5. Merge measurement types (_Eon, _Eoff, _Vfwd) into parent
    6. Create switching pair JSON with TDB-extended schema
    7. Skip unclear combinations (log to SKIPPED_FILES.json)
    8. Validate all fields

    Phase B: Existing TDB/File Exchange Migration (49 files)¶

    1. Read existing JSON (already TDB-native format)
    2. Wrap as self-pair (high_side = low_side = same device)
    3. Mark source='datasheet'
    4. Preserve all existing data (curves, ratings, thermal, capacitance)
    5. Write to switching_pairs/ directory

    Phase C: PLECS XML Migration (504 files)¶

    1. Parse XML using existing plecs_importer.py or custom parser
    2. Extract per-device data: conduction LUTs, switching energy LUTs, thermal model
    3. Create self-pair entries with PLECS analytical formulas preserved
    4. Merge with .mat data where same device exists in both
    5. Store PLECS formulas in plecs_model field

    Phase D: Deduplication & Merging¶

    1. Identify same device across sources (TDB + sc + File Exchange + PLECS)
    2. Merge by preference: DPT measurement > PLECS XML > datasheet
    3. Combine data: e.g., TDB has gate charge curves + sc has switching energy → merge both
    4. Generate conflict report for manual review

    root = tree.getroot()
    ns = {'p': PLECS_NS}

    package = root.find('.//p:Package', ns)
    vendor = package.get('vendor', '')
    partnumber = package.get('partnumber', '')

        'turn_off': turn_off,
        'conduction': conduction,

    sw = pair_json.get('switching_data', {})

    return {
        'name': pair_json['pair_id'],
        'blockingVoltage': hs['electrical_ratings']['v_abs_max'],
        'onStateVoltage': hs['conduction']['curves'][0]['on_state_voltage'] if hs.get('conduction', {}).get('curves') else [],
        'onStateCurrent': hs['conduction']['curves'][0]['on_state_current'] if hs.get('conduction', {}).get('curves') else [],
        'turnOnEnergy': sw.get('turn_on', {}).get('energy', {}).get('25.0', []),
        'turnOnCurrent': sw.get('turn_on', {}).get('current_axis', []),
        'turnOnVoltage': sw.get('turn_on', {}).get('voltage_axis', [400])[0] if sw.get('turn_on') else 0,
        'turnOffEnergy': sw.get('turn_off', {}).get('energy', {}).get('25.0', []),
        'turnOffCurrent': sw.get('turn_off', {}).get('current_axis', []),
        'turnOffVoltage': sw.get('turn_off', {}).get('voltage_axis', [400])[0] if sw.get('turn_off') else 0,
        'forwardThermalResistance': hs['thermal_properties'].get('r_th_jc', 0),
        'cost': hs['metadata'].get('cost', 0),
        'weight': hs['metadata'].get('weight', 0),
    }

    Risk Mitigation¶

    1. Data loss prevention: Original files never modified. All migration creates new files.
    2. Incremental migration: Can run Tasks 2-4 independently, merge later.
    3. Rollback: Delete switching_pairs/ directory to rollback entirely.
    4. Schema evolution: Version field allows future schema updates.
    5. Unknown formats: Files that can't be parsed are logged, not silently dropped.
