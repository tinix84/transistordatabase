    Web DPT native LTspice RAW import sprint¶

    Goal¶

    Let a local web user preview one native LTspice transient .raw file, choose its Vds and Id traces, mark turn-on and turn-off time windows, and append the resulting dpt_u_i measurement to a transistor's existing raw measurement records.

    This is a narrow import workflow. It does not derive switching energies, infer event boundaries, recognize a device trace from its name, or claim full desktop migration.

    Supported input and explicit limits¶

    • The parser is PyLTSpice RawRead from PyLTSpice 6.0.1 or later in the 6.x line. The project pins PyLTSpice>=6.0.1,<7.0 through requirements.txt, which is the dependency source used by pyproject.toml. The current RawRead API documentation documents native RAW filenames, dialect detection, trace lists, axes, and waveform access. The PyLTSpice project is GPL-3.0, matching the repository's GPL-3.0 license.
    • This sprint accepts only one native LTspice .raw result containing a single Transient Analysis plot with an unstepped, finite, nondecreasing time axis. Equal adjacent timestamps are accepted and retain source order. Multiple plots, parameter-stepped results, non-transient analyses, non-LTspice dialects, and other extensions return actionable errors.
    • The file is limited to 32 MiB, and each import endpoint rejects request bodies above 33 MiB (the file cap plus a 1 MiB multipart-overhead allowance) before Starlette multipart parsing. The body cap checks Content-Length and counts streamed chunks for requests without it; it does not retain a duplicate body buffer. Files are limited to 1,000,000 time points and 128 trace names. RawRead first parses the header only and applies the point/trace caps before reopening the file with only the explicitly selected traces, so the point cap protects waveform-array memory. Trace previews contain at most 800 points. The parser uses a request-scoped temporary directory and discards the temporary source file when each request completes.
    • DPT append and the opt-in stored-waveform GET (waveform_preview_points) read at most 64 MiB + 1 byte from the legacy device JSON before parsing; a larger file returns HTTP 413 with the byte limit and leaves it untouched. The cumulative raw_measurement_data compact JSON payload is capped at 32 MiB for append and opt-in preview. Append rejects a candidate above that payload cap or the 64 MiB indented device-file cap before writing, preserving all existing raw records. The DPT write path uses LF line endings so the UTF-8 indent=2 size check matches the actual output bytes on Windows and other platforms. The opt-in preview rejects a pre-existing raw payload above 32 MiB before model conversion or waveform serialization. Default /dpt_data calls retain the prior full-array response and do not apply these preview read caps. The 32 MiB payload cap accommodates one maximum 250,000-event-sample import in a representative numeric encoding (about 17.9 MB compact JSON for 500,000 persisted [time, value] pairs); repeated imports stop at the documented cumulative threshold.
    • Each event window accepts at most 250,000 samples, and turn-on plus turn-off together are capped at 250,000 source samples. At that combined cap, the three selected float64 arrays use about 22.9 MiB; the four persisted [time, value] pair lists use about 55 MiB of Python objects, approximately, with each time value shared by its Vds and Id pair. The request keeps one bounded upload bytearray and writes parser input to a temporary file. These figures exclude the loaded legacy database record and PyLTSpice internals; concurrent requests multiply per-request memory.
    • Trace names do not determine signal meaning. The parser identifies the file's time axis; the user explicitly selects Vds and Id. The user enters inclusive turn-on and turn-off time windows in seconds after inspecting the selected-trace preview. Non-finite Vds/Id values appear as JSON null gaps in the preview; they fail validation only when they fall inside a selected event window. A window with no samples, non-finite selected event values, or reversed boundaries fails before persistence.
    • Imported sample pairs remain [time_seconds, value] with Vds in volts and Id in amperes. Filtering preserves parser sample order, does not interpolate, and copies each selected event into one acquisition in the existing dpt_on_vds, dpt_on_id, dpt_off_vds, and dpt_off_id fields.
    • The user may enter optional conditions and provenance. Condition units are explicit in the form and stored-record view: temperature °C, voltage V, resistance Ω, and load/commutation inductance µH. The legacy RawMeasurementData convention stores inductances in microhenries, so the web form persists those numeric values unchanged.

    Persistence and compatibility boundary¶

    • The import route reads the upload before taking the record mutation lock, then reads the latest source JSON under that lock, appends one record to the existing top-level raw_measurement_data, validates a deep copy of the non-raw transistor payload with the legacy loader, and uses _write_legacy_record_unlocked for its atomic write. The atomic writer serializes the candidate directly; the route does not build a second full-record JSON string.
    • A legacy singleton raw-measurement object is retained as the first item when it is normalized into a list. The new list is shallow-copied, so existing raw measurement dictionaries and waveform arrays are retained without copying or replacement; unrelated source JSON fields are preserved. An unexpected raw_measurement_data shape causes a conflict and leaves the source file unchanged.
    • The route does not call the core repository save path because the legacy-to-core adapter drops top-level raw measurements. No database schema, TDB model, core adapter, ntbees2 interface/adapter/converter, device record, Qt path, or unrelated import/export behavior changes in this sprint.
    • Provenance records the uploaded basename, SHA-256 digest, parser and parser version, import timestamp, selected trace names, and the exact event windows. Uploaded .raw content is not persisted.

    Workflow and validation¶

    1. Upload a .raw file to inspect its plot type, sample count, time-axis name, and trace names.
    2. Select the Vds and Id traces and request a display-only preview. The preview keeps first/last display points and samples at most 800 points; it is not the persisted waveform.
    3. Enter both event windows in seconds and optional test conditions. The API reparses the same uploaded file, validates the requested traces and windows, and maps the exact source samples into the four existing event fields.
    4. Under the mutation lock, append the new record. On any parse, selection, model-validation, or serialization failure, the record is not written.

    The stored-waveform viewer requests waveform_preview_points=800. This opt-in GET projection uniformly samples each acquisition, retains its first and last points, and applies one deterministic 40,000-sample-pair budget across the whole response. The allocator shares the remaining budget across acquisitions while honoring the per-acquisition limit. Response metadata reports the requested per-acquisition cap, total cap, returned point count, and whether/how many acquisitions were downsampled; the UI displays that notice and renders waveforms without point markers. All raw records, metadata, and source samples remain unchanged. Calls that omit the query keep the existing full-array response contract. If retaining at least the endpoints of every non-empty acquisition would exceed the total budget, the preview request returns an actionable 413; records and metadata remain available through the default GET response.

    Focused acceptance evidence covers native parser success, invalid and unsupported files, preview non-mutation, trace and event-window mapping, inclusive boundaries, decreasing time-axis rejection, equal-time ordering, upload/request-body and append/opt-in-preview legacy-record file caps (including pre-parse rejection), the cumulative raw-payload append/read cap, default full-response behavior, JSON-safe non-finite preview gaps, combined event-sample bounds, additive append, prior raw-record and unrelated-field preservation, and failed-import non-mutation. Vue coverage exercises file preview, explicit signal mapping, manually entered windows, append, record refresh, stale file/trace/device previews, and stale DPT GET responses after device changes. A production build is required.

    The bounded GET projection is covered by API and UI tests: a 100-record, 160,000-source-point fixture returns exactly the 40,000-point aggregate cap with endpoints retained for all 400 acquisitions, and the source JSON bytes remain unchanged. Tests also verify the default GET omits projection metadata and continues to return complete samples, the API service sends the opt-in query, and DPTManager requests 800 points and labels the bounded view. Additional regressions prove appends above the 32 MiB raw-payload cap are rejected without mutation, existing raw payloads above the cap receive HTTP 413, oversized device JSON is rejected before JSON decoding, and a late DPT response cannot replace data for a newly selected device.

    Remaining gaps¶

    This sprint does not support stepped or multi-plot .raw results, other simulator dialects or file formats, automatic DPT boundary detection, waveform resampling, imported-energy derivation, raw-record editing/deletion, or screenshot parity. Full web capability coverage remains open.
