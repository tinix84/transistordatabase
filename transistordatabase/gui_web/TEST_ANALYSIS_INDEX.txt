TEST EXECUTION COMMANDS

To run tests, use these commands from the gui_web directory:

Quick Unit Tests:
  $ npm run test:run

  $ npm run test:coverage

E2E Tests:

  $ npm run test:e2e:ui

All Tests:
  $ npm run test:run && npm run test:e2e

  $ npm audit fix                       # Fix vulnerabilities

COMMON QUESTIONS & ANSWERS
================================================================================

Q: When should I run these tests?
A: Before every commit (CI/CD), definitely before releases, weekly for
   monitoring. See the test execution commands above.

Q: What if tests fail?
A: Review the specific test file, check the error message, and consult the
   Troubleshooting section in TEST_REPORT_README.md

Q: How long does the full suite take?
A: ~4-6 hours for all 5 browsers. ~30 minutes for single browser. Unit tests
   alone: 10-15 seconds.

Q: Do I need to run all 5 browsers?
A: For development: No, run just chromium. Before release: Yes, run all 5.

Q: What's the most important metric?
A: Unit test coverage >80% and E2E tests passing. Bundle size matters too.

Q: Can I run tests in parallel?
A: Yes, Vitest does this by default. Playwright tests run serially by default
   but can be parallelized.

Q: What do I do if the tests are flaky?
A: Check network connectivity, increase timeouts, ensure dev server running.
   See Troubleshooting section for details.

Q: How do I debug a failing test?
A: Run with --headed flag for E2E tests, add console logs, review playwright
   report for screenshots/videos.

Q: What's the success probability?
A: ~92% (accounting for environment setup, vulnerabilities to fix)
